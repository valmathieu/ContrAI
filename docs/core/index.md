# contrai-core

Shared domain model for the ContrAI workspace — pure data + invariants, no orchestration.

## Module map

Source lives at `packages/contrai-core/src/contrai_core/`:

| Module          | Contents                                                                                |
| --------------- | --------------------------------------------------------------------------------------- |
| `types.py`      | `Suit` / `TrumpVariant` / `Rank` enums, the `ContractSuit` union, and the `is_trump` / `trump_suits` predicates |
| `position.py`   | `Position` (the four seats; owns all seat arithmetic)                                   |
| `team_side.py`  | `TeamSide` (the two sides of the table — team *identity*)                               |
| `card.py`       | `Card`                                                                                  |
| `deck.py`       | `Deck`                                                                                  |
| `hand.py`       | `Hand` (append/extend/remove/clear/`in`/iterate/`len`, no indexing; its query helpers delegate to `card_queries`) |
| `card_queries.py` | `count_suit` / `cards_of_suit` / `has_suit` / `has_card` over any `Iterable[Card]` — the one implementation `Hand` and the play path's frozen tuples both read through |
| `team.py`       | `Team` (the two-player roster and its display name)                                     |
| `player.py`     | `BasePlayer` (engine `Player` extends it)                                               |
| `bid.py`        | `Bid`, `PassBid`, `ContractBid`, `DoubleBid`, `RedoubleBid` (frozen-dataclass sum type, generic over the actor), `seal_bid` |
| `auction.py`    | `Auction` (bidding-state rule oracle — see §below)                                      |
| `contract.py`   | `Contract`, `ObservedContract` (its seat-keyed projection)                              |
| `trick.py`      | `Trick`, `current_winner` (module-level trick-winner rule, shared with `PlayState`)     |
| `play.py`       | `Play`, `ObservedPlay`, `PlayState` (play-phase rule oracle — see §below), `PlayObservation` |
| `exceptions.py` | `ContraiError` (base), `InvalidPlayerCountError`, `InvalidCardCountError`, `InvalidCardError`, `IllegalBidError`, `IllegalPlayError` + `PlayRuleViolation`, `TrickStateError`, `InvalidContractError` |

Everything above is re-exported from `contrai_core/__init__.py` and is part of the public API — except `current_winner`, which stays a module-level import from `contrai_core.trick`.

## Class structure

```plantuml format="svg" source="class_core.puml"
```

The full domain model in one view. `Trick` is a dumb container of plays that does **not** store trump — `Trick.get_current_winner(trump_suit)` takes trump as a *required* argument and works on partial tricks. Nothing in the engine builds one any more — the play phase is `PlayState` end to end, and the trick-winner rule is reached through `PlayState.trick_winners`, the partner-master legality check, and the view's live winner highlight, all of which call the shared `current_winner` function below. `Trick` remains a public core type with its own tests; whether it still earns its place is an open question. `Bid` and its four variants are now frozen `@dataclass(frozen=True, slots=True)` value carriers — player is `field(compare=False)` so equality is *what was announced, not who announced it*, and the auction-state rules ("is this bid legal now?") live entirely on `Auction`. `Auction.is_legal` / `legal_actions` / `apply` replace what used to be `Bid.is_valid_after` and the `BidValidator` utility — including the *auction-freezes-after-a-Double* rule from `contree-domain.md §5.3`. `Auction.apply` raises `IllegalBidError` rather than silently downgrading an illegal bid to a Pass. The defending team is computed at the game level, where both teams are in scope — `Contract` only knows its own attacking side. See [Diagrams](../diagrams/) for the colour convention.

**Seats own the geometry; `TeamSide` owns the identity.** `Position`'s definition order *is* the anticlockwise turn order, and every geometric question derives from that one ordering rather than re-encoding it: `next`, `partner`, `opponents`, `is_teammate` ("same side?"), and `team_side` ("which side?"). `TeamSide` (`NS` / `EW`) is the team identity — the key `RoundScore.scores`, `Round.round_scores`, `PlayState.card_points_by_side` / `trick_counts_by_side`, `Game.scores` and `GameOverStatus` all use, and the token a persisted game record or a training label would serialize. It replaces what used to be the free-form `Team.name` string: a *display* label doubling as a dict key, which meant renaming a label silently broke a lookup and every call site quietly leaned on `Team`'s identity semantics (it has no `__eq__`/`__hash__`). Like `Position`, `TeamSide` is a plain `Enum` and not a `StrEnum`, precisely so the old string keys stop comparing equal — a leftover `scores["North-South"]` must miss loudly rather than resolve by accident. `is_teammate` is expressed *on top of* `team_side` (`self.team_side is other.team_side`), so the boolean and the value can never disagree. What is left of `Team` is the two-player roster plus its display name; it carries no identity and no score, and the partner/membership helpers that used to re-derive the pairing from the roster list are gone.

**Two suit types, one predicate.** `types.py` answers "what suit is this card?" and "what did the auction settle on?" with different types. `Suit` holds exactly the four card-bearing suits, so `tuple(Suit)` is safe to iterate anywhere a real suit is meant and `Card.__post_init__` can reject anything else outright (`InvalidCardError`). The two trump options that name no suit — `NO_TRUMP` and `ALL_TRUMP` — live on `TrumpVariant`, and `ContractSuit = Suit | TrumpVariant` is what a contract's trump is annotated as. It is a plain union assignment rather than a PEP 695 `type` alias on purpose: `isinstance(x, ContractSuit)` works on the plain form and raises `TypeError` on the alias form, and with no type checker configured in this workspace, `isinstance` narrowing is the only guardrail there is.

The two types meet in exactly one place, `is_trump(card_suit, contract_suit)`, plus its enumerating sibling `trump_suits(contract_suit)` and the `Card.is_trump(trump_suit)` sugar. Before that, the question was written out as `card.suit == trump_suit` at eleven sites in core and roughly as many again in the engine — a comparison that is only *accidentally* right for a trump naming no suit. It happens to answer correctly for `NO_TRUMP` (no card carries that suit, so every trump branch collapses to plain follow-suit, which is what a no-trump contract wants) and it answered the same way for `ALL_TRUMP`, where every card should be trump instead — so an all-trump contract played out as a no-trump one, silently. `is_trump` raises `NotImplementedError` there, and `ContractBid.VALID_SUITS` drops `ALL_TRUMP` altogether, so `Auction.legal_actions` offers 65 opening contracts rather than 78 and a future search-based agent sampling that set cannot reach a contract the engine will not play. **The variant itself is still unimplemented** — this makes the gap explicit and single-sited, it does not close it.

`play.py` adds the play phase's sibling to `Auction`: `PlayState` is an immutable frozen dataclass (`slots=True`) that owns the flat chronological tuple of `Play` records — `Play` is a `NamedTuple` of `(player, card)`, unpacking exactly like the tuples `Trick` and the winner rule already consume. Like `Auction`, the bare constructor performs no validation so tests and search forks can inject arbitrary mid-round states directly; `PlayState.start(contract, players, hands)` is the validated entry point for a fresh deal (exactly 4 players, 4 eight-card hands, 32 distinct cards). Every other view — `trick_number`, `current_trick`, `completed_tricks`, `trick_winners`, `card_points_by_side`, `trick_counts_by_side`, `to_act`, `is_terminal()` — is recomputed from `plays` on each access rather than cached; `slots=True` forbids stashing lazy state, keeping the play history the single source of truth. The last two answer "what has each side captured so far": every completed trick's pile and the trick itself are credited to the side of the seat that won it, scored through the contract's `TrumpRules`, with every `TeamSide` present as a key so callers index rather than `.get`. They carry the **raw pile only** — the +10 last-trick and +20 Belote bonuses are contract-conversion rules that belong to whoever scores the round, which is why a completed round sums to the deck's 152 and not 162. One derivation now serves the engine's scorer and both of its screens, where each used to re-sum a pile of its own. `legal_actions(player)` is the player-parametric legality oracle: it enforces the follow/trump obligations (follow suit; over-trump when trump is led; trump if void and the partner is not currently master, over-trumping an opponent's ruff if able; free discard once the partner is master, or once no obligation applies at all — no trump suit, or none held) but deliberately **no turn check** — the same idiom `Auction.legal_actions` uses for bids, so a caller can ask "what would be legal for this player" independent of whose turn it is. `apply(play)` is the single legality-enforcing transition: it checks turn order, then hand membership, then the obligations, raising `IllegalPlayError` with the matching `PlayRuleViolation` — `OUT_OF_TURN` (wrong player, or the phase is already over), `CARD_NOT_IN_HAND`, or one of `MUST_FOLLOW_SUIT` / `MUST_TRUMP` / `MUST_OVERTRUMP` — plus the legal alternatives for diagnostics. `with_hands(hands)` forks the same public history (contract, players, plays) onto replacement per-seat hands: the determinization primitive a future search-based AI would sample worlds from — no search runs on it yet, this is only the fork primitive.

`observe(player, bids=...)` is `PlayState`'s sanctioned trust boundary: it projects the omniscient state — which holds every seat's hand — down to a `PlayObservation` carrying only `player`'s own hand, the public trick history, the established contract, the auction history the caller passes in, and `player`'s legal cards right now. This is the input surface AI card-play strategies are meant to be handed, never the raw `PlayState`. **Everything is sealed on the way out**: every person the observation would otherwise name arrives as a bare `Position`, the opaque seat enum. The observer is `observation.position`, not a player; the trick history carries `ObservedPlay` `(position, card)` records rather than the state's own live-player `Play` records; the contract is an `ObservedContract` (`declarer`, `value`, `suit`, `doubled_by`, `redoubled_by`) rather than the live `Contract`; and each bid is reseated by `seal_bid` into a `Bid[Position]`, keeping its concrete variant and payload. The guarantee that falls out is a reachability one — *no* object path from an observation reaches a `BasePlayer` — and it has to be that strong, because a single surviving reference exposes `.hand` directly and, through `.team.players`, the partner's hand as well. `test_play_observation.py` asserts it by walking the whole object graph rather than by checking fields one at a time. `observe()` still takes the live player: the state needs that identity to look up the hand and the legal actions, so only the output is sealed. Trick-winner determination for both `Trick` and `PlayState` shares one implementation, the module-level `current_winner(plays, trump_suit)` function in `trick.py` — generic over the "who" slot of its plays, so it serves `(BasePlayer, Card)` and sealed `(Position, Card)` records alike: `Trick.get_current_winner` delegates to it, and `PlayState.trick_winners` / `PlayObservation.current_winner` (which therefore reports a `Position`) call it directly — `to_act` reaches the same rule indirectly, via `trick_winners` — one winner rule, not two that could drift apart.

**Exception hierarchy.** Every domain error now subclasses a single `ContraiError` base, so one `except ContraiError` catches the whole family. Each concrete error *also* subclasses `ValueError` (dual inheritance, `ValueError` kept in the MRO) so legacy `except ValueError` call sites keep working unchanged. `IllegalPlayError` is the card-play counterpart to `IllegalBidError`: it carries the offending `Card`, a machine-readable `PlayRuleViolation` reason (`MUST_FOLLOW_SUIT` / `MUST_TRUMP` / `MUST_OVERTRUMP` / `OUT_OF_TURN` / `CARD_NOT_IN_HAND`, a `StrEnum` for clean logging/JSON), and the set of legal alternatives — serving the §6.1 explainability goal and future RL/scraper/server consumers. `TrickStateError` (adding to a complete trick) and `InvalidContractError` (bad contract value/suit, or a redouble without an underlying double) replace the last bare `ValueError`s raised by `Trick`, `ContractBid`, and `Contract`.

## Consumers

- **`contrai-engine`** — direct dependency. Imports core types with `from contrai_core import …` and adds `Player` / `HumanPlayer` / `AiPlayer` / `Game` / `Round` on top.
- **`contrai-scraper`** — planned consumer. Observed games will be materialized into `Card` / `Bid` / `Trick` / … instances before being persisted to SQLite.
- **`contrai-analyzer`** — **does not** depend on core. The analyzer's `SuitSlot` (TRUMP/BLUE/GREEN/PURPLE) is a suit-agnostic abstraction for probability math, intentionally separate from `Suit` — it slots a hand by *role* relative to trump, where `Suit` names the four concrete suits. See the [analyzer overview](../analyzer/index.md).

## Conventions

- Type hints everywhere, including private helpers.
- Google-style docstrings on every public class/method/function.
- Didactic comments are welcome — this is a learning project.
- Every Model-layer addition ships with `pytest` tests under `packages/contrai-core/tests/`.

## Tests

Coverage is now complete across every module:
`test_types.py`, `test_position.py`, `test_team_side.py`, `test_card.py`, `test_deck.py`, `test_hand.py`, `test_card_queries.py`, `test_team.py`, `test_base_player.py`, `test_bid.py`, `test_auction.py`, `test_contract.py`, `test_trick.py`, `test_play_state.py`, `test_play_legality.py`, `test_play_observation.py`, `test_exceptions.py`.

`test_bid.py` covers the data contract of the frozen variants (construction validation, equality, ordering, `__str__`, immutability). The auction-state rules that used to be tested against `Bid.is_valid_after` and `BidValidator` now live in `test_auction.py` against `Auction.is_legal`, `legal_actions`, and `apply`. `test_play_state.py` covers `PlayState.start`'s validation, `apply`'s turn-order/hand-membership/immutability guarantees, `with_hands`'s determinization-fork validation, and the derived views' boundaries (including the no-trump degrade). `test_play_legality.py` exercises `legal_actions` against the follow/over-trump/trump obligation matrix and `apply`'s resulting `PlayRuleViolation` classification. `test_play_observation.py` covers `observe`'s own-hand-only projection, its legal-cards parity with `PlayState.legal_actions`, bids pass-through, the derived properties, immutability, the sealed trick records and sealed contract — and, in `TestNothingLiveIsReachable`, the seal itself stated as a property: a structural walk over the whole object graph of a fully populated observation (doubled contract, four-seat auction, a completed trick and a partial one) asserting that no `BasePlayer`, `Team` or `Hand` is reachable by any path, and that no `Card` outside the observer's own hand and the public history turns up. Two negative controls keep that walk honest — one confirms it finds the leaks in a live `Contract`, the other plants an unsealed `ContractBid` in an otherwise-sealed observation and confirms the walk reaches the player through it (a walk reading only `type(obj).__slots__` would miss it, since `ContractBid` inherits its `player` slot from `Bid`). `test_exceptions.py` covers the dual-inheritance invariant (every domain error is a subclass of both `ContraiError` and `ValueError`), the `PlayRuleViolation` `StrEnum`, and the message/attribute contract of each error; the construction-validation tests in `test_bid.py` / `test_contract.py` / `test_trick.py` assert the specific new types. The remaining engine-side gap is `Round` — see [`engine/index.md`](../engine/index.md#open-work).
